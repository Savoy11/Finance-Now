"Import trades from a file" on each tracked portfolio (`frontend/src/components/portfolio/tracked/ImportTradesPanel.tsx`) reads the CSV in the browser, never sending the file: a title line above the column names and a totals line below are set aside and shown; the person matches the columns, says what each value of the kind-of-trade column means (dividends, interest, deposits and conversions are left out by default) and which instrument each symbol is. Rules in `frontend/src/lib/data/tradeImport.ts` (tested); three new tables (`trade_imports`, `trade_import_rows`, `trade_import_layouts`) in migration 0010, which the owner runs with `npm run db:migrate`; until then importing answers 503 with that instruction and every other trade route is unaffected. "Download my data" (D199) includes the new tables without being told. Checked on a built app against a real PostgreSQL 16 database: two saves sent at once saved the file once, the same file again saved nothing, cancelling restored the holdings, and the import screen worked in a browser. Starting positions, splits, dividends and income are still entered by hand (T-451 covers income). |
| D201 | Next to build after T-447, Claude recommended T-451, recording dividends, interest and staking rewards in a tracked portfolio: tracked portfolios recorded no income, so a dividend payer's or a staked coin's return was understated, and broker files' dividend rows were left out of an import. Its proposal named one question: what a unit received as income costs, for the gain when it is later sold: its value on the day as entered (recommended), or zero. | Owner chose T-451, with units received costing their value on the day (the recommended option). | Built. Two new kinds of entry on a tracked portfolio: **cash income** (a dividend, interest or a fund distribution: an amount, a kind and a date; no units move, so no cost or gain changes) and **units received** (a staking reward or a dividend paid in shares: units and their value per unit that day, a new lot whose cost is that value, so a later sale's gain starts from there). Both count as income received, shown apart from the gains: a fifth "Income received" box with the last 12 months, and an Income column per holding. The rules are in `frontend/src/lib/data/costBasis.ts` and `tradeLedger.ts` (tested); cash income's amount and kind are kept in a table of their own, `trade_income`, added by migration 0011, which the owner runs with `npm run db:migrate`; until then recording cash income answers 503 with that instruction and nothing else changes. Units received need no new table. The trade import (D200) now reads a dividend, interest or distribution row as cash income from the file's amount column, and a staking reward row as units received at the file's price that day; interest charged (margin interest) is not income, and a negative amount is refused rather than read as income. "Download my data" (D199) carries each income row's amount and kind. The methods page gains "Tracked portfolios: gains and income" (D163). No tax rule is applied to any of it; the federal sale-tax estimator stays parked behind D4 (T-058). |
