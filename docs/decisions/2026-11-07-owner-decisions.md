"Import trades from a file" on each tracked portfolio (`frontend/src/components/portfolio/tracked/ImportTradesPanel.tsx`) reads the CSV in the browser, never sending the file: a title line above the column names and a totals line below are set aside and shown; the person matches the columns, says what each value of the kind-of-trade column means (dividends, interest, deposits and conversions are left out by default) and which instrument each symbol is. A coin is only ever the coin the person picks, suggestions from the catalog included, never matched by its ticker (D190); a currency code such as USD is cash and left out. Every row is shown with what it becomes, and each passes `parseTradeInput`, as a typed trade does; numbers are read as text, a decimal comma or another currency is refused rather than guessed. `POST /api/user/tracked-portfolios/[id]/imports` checks the rows again, says which an earlier import already saved (not saved twice) and which match a trade typed by hand (held back unless the person includes them), and what the lot engine would say (a sale of more than was held); it then saves them together under a lock on the portfolio, with the layout to remember for files with the same column names. `POST …/imports/[importId]/cancel` cancels a whole import by adding a cancellation row for each of its trades: nothing is changed or removed, the trades stay listed as cancelled, and the file can be imported again. Rules in `frontend/src/lib/data/tradeImport.ts` (tested); three new tables (`trade_imports`, `trade_import_rows`, `trade_import_layouts`) in migration 0010, which the owner runs with `npm run db:migrate`; until then importing answers 503 with that instruction and every other trade route is unaffected. "Download my data" (D199) includes the new tables without being told.
