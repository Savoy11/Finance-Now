(2) **Dark like D232**: the Settings card renders nothing without a real session, and every `/api/user/two-factor/*` route resolves the account through `getSessionUserId()` only — never the shared local user, where second-step protection would protect nothing while looking protective. (4) **Sign-in** asks only after the password matches (then after the forced-reset check): `totp_required`, `totp_invalid`, `totp_throttled`; ten one-time recovery codes stored as SHA-256; a used code's step is recorded so it cannot be replayed; five wrong codes make the account wait five minutes, counted in server memory (the D173 posture).
